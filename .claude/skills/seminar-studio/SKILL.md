# 세미나 스튜디오 오케스트레이터

흐름은 `workflows/seminar.workflow.mjs`가 강제한다. 이 스킬이 하는 일은 **컨텍스트 판별과
브리프 컴파일** 둘뿐이다. 순서를 여기서 다시 설명하지 마라 — 스크립트가 정본이다.

## Phase 0: 컨텍스트 확인

| 상태 | 행동 |
|------|------|
| `_workspace/` 비어 있음 | 초기 실행. Phase 1로 |
| `_workspace/02_core.json` 있음 + **부분 재제작** 요청("카드뉴스만 다시") | 전사·분석을 건너뛴다. §재실행 참조 |
| `_workspace/` 있음 + **새 입력 파일** | 기존을 `_workspace_prev/`로 옮기고 초기 실행 |
| 직전 실행이 중단됨 | `resumeFromRunId`로 재개를 먼저 검토한다. 완료된 단계는 캐시로 즉시 반환된다 |

입력 파일은 `input/`에서 찾는다. 여러 개면 사용자에게 어느 것인지 확인한다.

## Phase 1: 브리프 컴파일 — 요청 원문을 그대로 넘기지 않는다

"세미나 정리해줘"를 에이전트에게 그대로 던지면 에이전트가 청중과 톤을 각자 상상한다.
산출물 품질은 브리프 품질을 못 넘는다. 아래를 채워 `args.brief`로 만든다:

```json
{
  "topic": "세미나 주제 — 전사 --initial-prompt에 그대로 들어간다",
  "speakers": ["발표자명"],
  "terms": ["고유명사·전문용어 — 전사 정확도의 가장 큰 레버"],
  "audience": "누가 읽나 (사내 공유 / 외부 SNS / 경영진 보고)",
  "tone": "격식 | 캐주얼",
  "emphasis": "특별히 살릴 축이 있으면",
  "assumptions": ["원문에 없어서 내가 정한 것 — 반드시 사용자에게 보이게 남긴다"]
}
```

- **`terms`를 비우고 실행하지 마라.** 한국어 전문용어가 일상어로 뭉개진다("에이전트"→"에이전시").
  사용자가 안 줬으면 파일명·폴더명·세미나 제목에서 뽑고 `assumptions`에 적는다
- 질문은 **진짜 갈림길일 때만 1문항.** 청중이 사내인지 외부인지는 4종 전부의 톤을 바꾸므로
  물을 값어치가 있다. 나머지는 기본값(사내 공유 / 격식)으로 정하고 `assumptions`에 남긴다

## Phase 2: 실행

```
Workflow({ scriptPath: "workflows/seminar.workflow.mjs",
           args: { input: "input/<파일>", brief: {…} } })
```

- 이미 전사본이 있으면 `args.transcriptPath`를 넣는다 (전사 단계를 건너뛴다)
- 백그라운드로 돈다. 완료 알림을 기다리고 **그 사이 결과를 예단하지 마라**

## Phase 3: 보고

반환값에서 반드시 사용자에게 전달할 것:
- `factcheck.pass` — **false면 먼저 말한다.** 환각·오인용이 남은 산출물을 그냥 넘기지 마라
- `missing` — 만들어지지 않은 format이 있으면 숨기지 않는다
- `core.confidence`가 `low`면 그 이유와 함께
- `core.assumptions` — 내가 정한 것들. 사용자가 이걸 봐야 다음 실행에서 고칠 수 있다
- 산출물 경로 4종 + Artifact URL

산출물 본문을 대화로 옮기지 않는다. 경로와 한 줄 설명만.

## 재실행 / 부분 재제작

| 요청 | 실행 |
|------|------|
| "카드뉴스만 다시" | `seminar-composer`를 `format: cardnews`로 **Agent 직접 호출.** 워크플로우 전체를 돌리지 마라 |
| "톤을 캐주얼하게, 4종 전부" | 브리프의 `tone`만 바꿔 `Workflow` 재실행. 전사본이 있으므로 `transcriptPath`를 넘긴다 |
| "요약이 틀렸다 / 이 인용 이상하다" | 지적사항을 `seminar-analyst`에 넘겨 코어를 고친 뒤, 영향받는 산출물만 재생성 |
| 새 녹음 | `_workspace_prev/`로 이관 후 전체 실행 |

**코어를 고쳤으면 그 코어를 참조하는 산출물을 전부 다시 봐야 한다.** 4종은 용어를 공유하므로
하나만 고치면 서로 다른 말을 하게 된다.

## 실패 시

- 반환값이 비었거나 이상하면 transcript 디렉토리의 `journal.jsonl`부터 읽는다 (각 agent의 실제 반환값)
- 전사 실패는 대개 모델 다운로드 또는 코덱. `.claude/skills/seminar-transcribe/SKILL.md` §6 참조
- `deck` 실패는 대개 python-pptx 미설치. `.venv/bin/python -c "import pptx"` 로 확인

## 트리거 경계 — 이 스킬이 **아닌** 것

| 요청 | 어디로 |
|------|--------|
| "회의록 써줘", "미팅 노트 정리" | `meeting-notes-writer` (전역). 회의는 의사결정 기록이 목적이고, 세미나는 지식 전달이 목적이라 산출물 구조가 다르다 |
| "전사만 해줘", "받아쓰기" | `seminar-transcribe` 스킬 단독. 4종을 뽑지 마라 |
| "카드뉴스 만들어줘" (세미나 소스 없음) | `design` 스킬. 이 하네스는 **세미나 코어가 있을 때만** 쓴다 |
| "이 녹음 뭐라고 하는지 알려줘" | 전사 후 직접 답한다. 파이프라인 전체는 과하다 |

## 테스트 시나리오

**정상 흐름:** `input/seminar.m4a`(90분, 한국어) + "사내 공유용으로 정리해줘"
→ 브리프 컴파일(청중=사내, terms=파일명·제목에서 추출) → Workflow 실행
→ 전사(haiku, ~5분) → 코어 → 팩트체크 pass → 4종 병렬
→ 보고: 경로 4개 + Artifact URL 2개 + assumptions 목록.

**에러 흐름:** 팩트체크가 `misquote` 2건으로 fail
→ 분석 담당이 해당 항목만 수정 → 재검증 → 통과 시 산출 진행.
2회 후에도 미통과면 **산출은 진행하되** `notes`에 미통과를 명시하고,
사용자에게 issues를 먼저 보고한다. 조용히 넘기지 않는다.
